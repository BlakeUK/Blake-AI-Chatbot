1. Quick start: your first QR code

What it is. The shortest route to a working, tracked QR code.

  1. Press New QR code in the menu.
  2. Choose Dynamic (tracked) and Website link.
  3. Give it a Name (for example "Autumn leaflet") and a Campaign (for example "Leaflet").
  4. Paste the web address you want people to reach, starting with https://.
  5. Look at the preview on the right. Change the colours or add your logo if you like.
  6. Press Create QR code.
  7. On the page that opens, download the picture: SVG for printing, PNG for documents and screens.
  8. Scan it with a phone before you print anything. Check it opens the right page.
  9. Come back to this code's page at any time to see how many people have scanned it.

2. The Codes page

What it is. A list of every QR code, newest first. It is the page you land on after signing in.

How to use it.

  • Name: click it to open the code, download it, edit it and see its statistics.
  • Type and the green dynamic or grey static badge show what kind of code it is.
  • Campaign: click one to show only the codes in that campaign. Press clear to see everything again.
  • Short URL: the tracking address inside a dynamic code. Static codes do not have one.
  • Destination: where a scan goes, with a friendly name such as Facebook or "Blake UK website".
  • Window: scheduled (not started yet), active (counting now) or ended (no longer counting, though the code may still work), with the dates.
  • Scans and Unique: how many scans and how many different visitors. Bots are not counted. See Reading the statistics.
  • With more than 25 codes the list is split into pages; use Newer and Older at the bottom.

3. Static or dynamic: which should I choose?

What it is. The one big choice you make for every code, and it cannot be changed afterwards.

Dynamic (tracked)Static
What the picture containsA short address on this system. Scans pass through it and are then sent on.The content itself (the web address, the Wi-Fi details, the contact card...).
Counts and analyses scansYesNo: scans never reach this system.
What is recorded about each scanTime, approximate place, device, system, browser, language, where sent, referring site name and a scrambled visitor token (full list: What is tracked)Nothing at all
Change where it goes after printingYes, any timeNo, never. Make a new code.
Start and end dates, scan limit, password, smart routingYesNo
Works without internet and without this systemNo: it needs this system to be runningYes, for ever
The pictureSimple and easy to scan, because the address is shortDenser if the content is long

Rule of thumb. Anything for marketing, packaging or print that you want to measure or might need to fix: dynamic. Wi-Fi, a fixed message or a contact card that will never change and must always work: static. If you are unsure, choose dynamic.

Some types are only possible one way. Wi-Fi and Plain text are static only (the phone is not online yet when it scans a Wi-Fi code). App stores and Smart URL are dynamic only (they need this system to decide where to send each person). The chooser only offers combinations that work.

You cannot turn a static code into a dynamic one later, because the content is already printed inside the picture.

4. What is tracked, and privacy

What it is. A plain list of everything this system records about people, feature by feature, so nobody has to guess. It is built from the same description the system is tested against, and it is repeated in the PDF manual.

In short

  • A dynamic QR code records each scan. A static QR code records nothing.
  • A link page records each view and each press of a web button. Email and phone buttons are not recorded.
  • No names, no email addresses, no tracking cookies and nothing the visitor types. (The only cookie a visitor can ever receive is a 30-minute security token on the password page of a protected code; it holds nothing about them.)
  • {{if .Data.FullIP}}Full internet-address storage is switched ON for this system, so each scan of a QR code keeps the visitor's actual address as well as the scrambled token. Your privacy notice must say so.{{else}}The visitor's internet address is not stored. It is used for a moment to estimate the place and to make a scrambled token, then thrown away.{{end}}
  • Records are deleted automatically after {{.Data.RetentionDays}} days.
  • Everyone who is signed in can see the statistics and download exports. Visitors can see nothing.

The scrambled visitor token

To count "unique" visitors without keeping anyone's address, each visit is given a token: a one-way scramble of the visitor's internet address mixed with a secret that is made fresh every day. The same person gets the same token all day, so they are counted once. The token cannot be turned back into an address, and tomorrow's token for the same person is different, so people cannot be followed from day to day. The daily secrets are deleted after three days.

Places are estimates worked out from the internet address using a free location database. Country is usually right; town and region are guesses.

Your responsibilities

  • Your privacy notice should say that scans of QR codes and visits to link pages are counted, with approximate location, device details and language, and how long they are kept. If full-address storage is on, it must say that too.
  • Exports are personal data. A CSV includes the scrambled token and the browser's identification text for every scan. Store and delete exports as you would any personal data.
  • Because no name or address is kept, an individual scan cannot be linked to a person afterwards. There is also no way to delete a single scan; deleting a QR code or a link page deletes all of its records, and everything else is deleted automatically when it reaches {{.Data.RetentionDays}} days.
  • The web server keeps its own system log. Visitor addresses, cookies and the referring page's address are removed from it, but it does keep the address requested, the browser's identification text and the language setting, under the server's own retention settings.

5. Making a QR code, step by step

What it is. The form where you say what the code does and how it looks. Press New QR code, then choose a type.

  1. Details. The Name is only for you. The Campaign groups codes by where they are used (see Campaigns). Typing in the campaign box suggests existing ones, and "Leaflet" and "leaflet" are treated as the same campaign.
  2. The type's own boxes. What you enter depends on the type; the grey text under the heading tells you. See Every type of QR code.
  3. Tracking window and Limits and protection (dynamic codes only). See Tracking window and Scan limits and passwords.
  4. Design. Colours, shapes, frame, text and logo, with a live preview. See Designing the look. You can also save the design for next time: How to save and reuse designs.
  5. Press Create QR code. If something is wrong, the page stays open and tells you what to fix, next to the box concerned.

Boxes marked with an asterisk (*) are required. The form refuses anything that would make a broken code: a web address that is not http or https, a design too pale to scan, content too long to fit in a QR code, and so on.

7. Designing the look of a code

What it is. The Design panel changes how the code looks without changing what it does. The picture on top is a live preview of a sample code. How to use each control:

Code colour and Background
The colour of the dots and of the paper behind them. The code must be darker than its background and the contrast must be at least 4 to 1. If you choose pale yellow dots, or a light code on a dark background, the preview shows a message and the form will not save it: many phone cameras cannot read those.
Dot style
square (classic), rounded (softened squares) or dots (circles).
Corner style and Corner colour
The three large squares in the corners. square, rounded or circle. Tick Corners match the dots to use one colour, or untick it to colour the corners differently (they must also be dark enough).
Frame and Text under the code
none, box (a coloured border with a label underneath) or banner (just a label strip). The text is up to 24 characters, for example "SCAN ME" or "SCAN FOR THE MANUAL". If you choose a frame and leave the text empty it says "SCAN ME".
Error correction
How much of the picture can be dirty, scratched or covered and still scan. L 7%, M 15% (the default), Q 25%, H 30%. Higher is more forgiving but makes the code denser. Use H on rough surfaces such as packaging.
Logo in the centre
Upload a PNG, JPEG or GIF up to 1 MB. It is resized to fit in the middle, covering about 5% of the code. A logo hides part of the code, so the error correction is raised to at least Q automatically. The upload is re-saved as a clean image; other kinds of file are refused.

The preview and the real thing. The preview is a sample of how the style looks; the real code holds your real address. Always scan a real printed code with a phone before you use it.

Safe combinations. Every colour, shape, frame and logo combination offered here has been tested by decoding the result with real QR-reading software. If something is risky, the form refuses it rather than letting you print a code that does not work.

8. How to save and reuse designs

What it is. A saved design remembers the whole look under a name: colours, dot and corner styles, frame, text, error correction and logo. Use it to keep every code on-brand without setting everything up again.

Saving a design: two ways

Way 1: on its own (easiest).

  1. Press Designs in the menu, then New design.
  2. Choose the colours, shapes, frame, text and logo. Watch the preview.
  3. Type a name under Save this design to use again, for example "Blake UK blue".
  4. Press Save design. You land on the Designs page and see it there with a thumbnail.

Way 2: while making or editing a code.

  1. Set the design as you like in the Design panel.
  2. Type a name in the Design name box under Save this design to use again.
  3. Either press Save design only (saves just the design; your code is not created yet), or press Create QR code / Save changes (saves the design and the code).

If you press Save design only without typing a name, the page asks you for one.

Using a saved design

  • When making a code: choose a type, and under Design click the design's name next to Use a saved design. The panel fills in with it (including the logo). You can still adjust it for this code.
  • From the Designs page: press Use for a new code under a design. That opens the form for a website link with the design applied; change the type from the New QR code chooser if you need a different one.
  • In bulk: pick it from the Design list on the Bulk page so that every code in the batch uses it.

Changing, replacing and deleting

  • Change a design: Designs, then Edit under it, make your changes and press Save design. Because the name is the same, it replaces the old version.
  • Save a variation: open a design with Edit, change the name, and save. You now have both.
  • Delete a design: press Delete under it and confirm. Codes already made with it are not affected.

Good to know

  • Designs are shared by everyone who signs in, so a colleague can use the brand design you saved.
  • A design only stores the look. It never contains a web address or any content.
  • Applying a design copies it to the code. Editing the saved design later does not change codes already made; to restyle an existing code, open it and use Edit.
  • Design names are not case sensitive ("Blake blue" and "blake BLUE" are the same name) and can be up to 60 characters.

9. Tracking window and what happens at the end

What it is. For a dynamic code, the dates during which scans are counted. How to use it.

  • Preset: 24 hours, 7, 30 or 90 days, counted from the moment you press Create.
  • Custom: choose Custom and type the start and end, in UK time. Daylight saving is handled for you.
  • Before the start the code already works and sends people on, but the scans are not counted.
  • When the window ends (or the scan limit is reached) the code does one of three things, your choice: keep redirecting and stop counting (the default, so printed codes never break), show an "expired" page, or send people to a fallback address such as your home page.
  • You can edit the window at any time, for example to extend a campaign. Scans already recorded stay.

The code status on the Codes page is scheduled, active or ended. A code you have switched off shows a disabled badge.

10. Scan limits and passwords

What they are. Two optional controls on a dynamic code.

Scan limit. Stops the code after that many people have scanned it. Bots and link-preview robots do not use up the limit. When it is reached the code behaves as if its window had ended (see above). Leave the box empty for no limit. The code's page shows how many have been used, for example "37 of 500 used". Raising the limit by editing brings the code back to life.

Password. Visitors see a page asking for the password and are only sent on when they type it correctly. Good for trade-only pages. Notes:

  • The password is 4 to 72 characters. It is stored scrambled, never readable.
  • A visit is only counted as a scan once the right password is entered.
  • Wrong guesses are slowed down: after six in a minute a visitor has to wait.
  • Editing a code with the password box empty keeps the current password. Tick Remove the password to take it off, or type a new one to change it.
  • The password protects the destination, but the printed code itself is not secret: anyone can scan it and see the password page.

11. Sending people to different places (smart routing)

What it is. One printed code that sends different people to different addresses, for a dynamic code of type App stores or Smart URL.

How to use it.

  • App stores: enter your App Store link, Google Play link and a web page for everyone else. iPhones and iPads go to the first, Android to the second, all others to the third.
  • Smart URL: set a default address, then up to five rules. Each rule has three parts: what to look at (operating system, device type, language or country), the value, and where to send people who match. Rules are checked from top to bottom and the first match wins. Anyone matching none goes to the default.
  • Values: operating system is iOS, Android, Windows, macOS, Linux or ChromeOS. Device is mobile, tablet or desktop. Language is a code such as en or fr-FR (cy matches Welsh in any region). Country is a two-letter code such as GB or FR.
  • Each scan records where that visitor was actually sent, so the statistics show how your rules are used.
  • Country rules rely on the approximate location database; if a visitor's country cannot be worked out, a country rule will not match them.

12. What your visitors see

What it is. The experience of the people who scan your codes or open your link pages, so you know what to expect and what to tell them.

An ordinary dynamic code
The visitor is sent straight on to the destination. Nothing is shown from this system, and it takes a fraction of a second.
A code that has not started, or has ended
While the tracking window has not started, the code works but is not counted. When it has ended (or the scan limit is reached) it does what you chose: keeps redirecting without counting, shows an This link has expired page, or sends the visitor to your fallback address.
A password-protected code
A page titled This code is protected asks for the password. The right password sends the visitor on. A wrong one shows That password is not right. After six wrong guesses in a minute they must wait.
A code you have switched off
Link disabled: this link has been switched off.
A code that was deleted, mistyped or never existed
Link not found.
Too many visits from one visitor
Too many requests: please wait a minute. This only affects someone making more than 30 requests a minute.
A contact card (vCard) or calendar event code
The phone offers to save the contact or add the event.
A smart-routing or app-stores code
The visitor is sent to whichever address matches their phone, language or country, with no page in between.
A static code
The phone acts on the content directly (opens the web address, joins the Wi-Fi, shows the text). This system is not involved.
A link page
A page with the company logo, the heading and a row of buttons. Pressing a web button goes through this system for a moment, to be counted, and on to the destination. Email and phone buttons open the visitor's own app directly. A page that is switched off, deleted or mistyped shows Page not found.

Visitors never see a sign-in page or any of the admin. None of these pages asks them for any personal details.

13. Downloading, printing and testing

What it is. Getting the picture out of the system and onto paper or a screen. Open a code and use the QR code panel.

  • SVG is a vector picture that stays sharp at any size. Use it for anything professionally printed, and give it to your printer.
  • PNG 256, 512, 1024 are ordinary pictures that many pixels wide. Use them in documents, emails, slides and websites. 1024 is best for anything that will be enlarged. A code with a frame is taller than it is wide.
  • The download always uses the code's current design. If you change the design, download it again.
  • The picture of a dynamic code does not change when you edit where it goes, so printed copies stay valid.

Printing checklist.

  1. Make it big enough: at least about 2 cm (0.8 in) across for scanning from close up, and bigger for posters or anything scanned from further away (as a rough guide, one tenth of the scanning distance).
  2. Keep the blank border around the code. Do not crop it, and do not print over it.
  3. Keep strong contrast: dark code on a light background. Never print it inverted (light on dark).
  4. Avoid shiny, curved or heavily textured surfaces that reflect light. On rough or curved surfaces use error correction H.
  5. Scan a printed test with two different phones (one iPhone and one Android if you can) before printing the full run.

14. Reading the statistics

What it is. Open any dynamic code to see how it is performing. Static codes have no statistics, because their scans never reach this system.

All scans
Every visit by a person while the code was being tracked.
Unique
Different visitors. A visitor counts once in any 24 hours, so someone who scans three times in a morning is one unique visitor. The figure uses a scrambled form of their internet address, not the address itself.
Bots
Robots, not people: search engines, and the "link preview" fetchers that chat apps like WhatsApp and Slack use when a link is pasted. They are recorded but kept out of the headline numbers. Press Include bots to see them, or Hide bots to hide them again.
Scans over time
A bar chart in UK time: by the hour when the tracking window is under three days, otherwise by the day. Hover over a bar for its number.
Breakdown boxes
The ten most common values for device (mobile, tablet, desktop), operating system, browser, language, country, region, town and referring site, each with a percentage.
Referrer
The website or app the visitor came from, when their phone tells us (for example l.facebook.com). Only the site name is kept, never the full address.
Individual scans
Every scan, newest first, 50 to a page: exact UK date and time, campaign, approximate place, device, system, browser, language and where they were sent. New visitor marks someone not seen on this code in the previous 24 hours.
Place
Worked out from the visitor's internet address using a free location database, so it is an estimate. Country is usually right; the town is often just the nearest big town; mobile networks and VPNs can show the wrong region.
Export CSV
Downloads the scans as a spreadsheet file. Export CSV on a code gives that code; Export scans in the menu gives every code, with the campaign on each row. Times appear in both UTC and UK time.

15. Exporting your data (CSV)

What it is. A spreadsheet file of scan records, to open in Excel or Google Sheets. How to use it. On a QR code's page press Export CSV for that code, or press Export scans in the menu for every code. Link pages have no export yet.

What is in it. One row per scan, oldest first, including robots, which are marked is_bot = 1 so you can filter them out. Columns:

scanned_at_utc, scanned_at_localThe time, in UTC and in UK time.
campaign, link_label, link_codeWhich campaign, which code (its name) and its short code.
destination, destination_siteWhere that visitor was sent, and a friendly name for the site.
country, region, townEstimated place.
language, device, os, browserThe visitor's language setting and device details.
referrer_hostThe name of the site or app they came from.
is_bot, is_unique1 or 0.

ip_hashThe scrambled visitor token (changes daily).
user_agentThe browser's full identification text.

Text that a spreadsheet could mistake for a formula is prefixed with an apostrophe, so opening an export cannot run anything. Anyone who is signed in can export, so handle the files as personal data (see What is tracked).

16. Campaigns

What it is. A short label saying where a code is used: Leaflet, Exhibition stand, Product box, Van, Trade counter and so on. It is how you compare placements.

How to use it.

  • Set it when you create or edit a code. Type your own or pick a suggestion.
  • The Campaigns page adds up the scans, unique visitors and bots for every campaign, with the last scan time. Codes with no campaign are listed last.
  • Click a campaign name, on that page or on the Codes page, to list just its codes.
  • Capital letters do not matter: "Leaflet" and "leaflet" are one campaign. Names can be up to 60 characters.
  • It is one flat list (no folders inside folders).

17. Editing, disabling and deleting a code

What it is. The buttons at the top of a code's page.

  • Edit. A dynamic code: change the name, campaign, destination or contents, window, limits, password and look. The tracking address and the type never change, so printed codes keep working. A static code: only the name, campaign and look can change, because its content is printed in the picture.
  • Disable / Enable (dynamic only). Switches the code off without deleting it: visitors see a "Link disabled" page. Enable turns it back on. Use it to pause a campaign.
  • Delete. Removes the code and all its scans, and cannot be undone. A deleted dynamic code stops working wherever it is printed (scans show "Link not found"). Deleting a static code does not affect printed copies, which keep working.

18. Making many codes at once (bulk)

What it is. One tracked code per row of a spreadsheet, returned as a ZIP file. Good for a catalogue of products. Open Bulk in the menu.

  1. In your spreadsheet put the headings label and url in the first row (and optionally campaign), then one code per row. Save as CSV. Example:
    label,url,campaign
    Aerial A1 box,https://www.blake-uk.com/aerials/a1.html,Product box
  2. On the Bulk page choose the file.
  3. Set a default campaign for rows without one, the tracking window, and the images you want (SVG only, PNG only, or both).
  4. Optionally pick a saved Design (so all the codes match your brand) and the error correction.
  5. Press Create codes and download ZIP.

The ZIP holds a picture of each code (named by its code) and codes.csv, which lists each row's label, campaign, destination, tracking address and code so you can match them to your products.

  • All or nothing: if any row is wrong (for example an address that does not start with https://), nothing is created and the page lists the rows to fix, by spreadsheet row number.
  • Limits: up to 1,000 rows when you ask for SVG only, and up to 250 rows when PNG is included (PNG takes longer to draw). Split larger files.
  • Bulk makes dynamic website-link codes. They appear on the Codes page like any other.

19. Link pages (like Linktree)

What it is. A link page is a web page, hosted here, that gathers all of a company's links in one place: website, social media, email, phone. It carries the company's logo and a theme, works well on a phone, and counts how many people open it and which buttons they press. Open Link pages in the menu.

Use it where you can only give one address: a social media profile, an email signature, a business card, a poster. Or make a QR code that opens it (see below).

Making a page

  1. Press New link page. To save time, use Start from an example on the Link pages page: it fills in a page for Blake UK, VisionPlus or Solwise. The example addresses are placeholders: check every one before you publish.
  2. Company. Click Blake UK, VisionPlus or Solwise. This sets the logo and the company's colours.
  3. Theme. Click one and watch the preview:
    • Midnight: deep navy, glowing curves in the accent colour, glass-style buttons with round icon badges and a row of social tiles at the bottom.
    • Daylight: light and clean, white buttons on a soft background, the company colour for the icons.
    • Bold: a dark page tinted with the company colour, with solid, company-coloured buttons.
    Dark themes use the company's logo made for dark backgrounds; Daylight uses the one for light backgrounds. You can change theme at any time without losing anything.
  4. Accent colour. By default the page uses the company's own colour. To use a different one, untick Use the company's own colour and pick one. If it would be hard to read on that theme (for example navy on Midnight), the form explains and refuses it.
  5. The page. The Name is just for you. The Page address is the part after /l/ in the web address; leave it empty to use the name. Lower-case letters, numbers and dashes only. The Heading appears under the logo ("Official Links" if left empty) and the Subheading is optional. Two tick boxes choose whether each button shows its web address underneath and whether the social icons row appears.
  6. Buttons. For each button give a Title and an Address:
    • A web address starting https:// opens that page.
    • mailto:name@example.com starts an email.
    • tel:+441142235000 offers to call that number.
    The Icon is chosen from the address (Facebook, Instagram, LinkedIn, TikTok, YouTube, X, Pinterest, WhatsApp, email, phone, location, or a globe) unless you pick another. Small text replaces the address shown underneath. Use the arrows to move a button up or down and the cross to remove it. Empty rows are ignored. A page can have up to 30 buttons. Use Add another button for more rows.
  7. Live preview. The phone beside the form shows your page as it is right now, including things you have not saved. Buttons in the preview open in a new tab. Nothing is published or counted until you press Create page (or Save changes).

Sharing it, and a QR code for it

  • After saving, the page's own screen shows its public address with a Copy button. Anyone can open it; no sign-in is needed.
  • Press Make a QR code for this page. This makes a normal, tracked QR code (see Making a QR code) in the company's colour with the words "SCAN FOR OUR LINKS". Use Edit on that code to change its colours, frame or logo, then download it as usual. You can make as many as you like, for example one for a poster and one for a leaflet, and give each its own campaign.
  • Visits that arrive through a QR code are counted separately as via a QR code.

Views or clicks: what is the difference?

A view is someone opening the page. A click is someone pressing a button on it. They count different things, so the two numbers are not the same and you should not expect them to match.

ViewsButton clicks
What it countsEach time the page is openedEach press of a web button on the page
One person can makeMany: a reload or a return visit counts again. Unique visitors counts them once a day.Many (several buttons, or one button twice), or none at all
Email and phone buttonsNot applicableCannot be counted: they open the visitor's own app directly
Bots and link previewsLeft outLeft out
Where you see itViews, Unique visitors, Via a QR code, Views over timeButton clicks, Pressed a button, Clicks on each button

An example. Your poster has a QR code that opens the page, and 100 people scan it. The code shows 100 scans. The page shows 100 views, all marked via a QR code. Sixty of them press at least one button and some press two, so the page shows 85 button clicks and 60% pressed a button. Views tell you how many people arrived; clicks tell you what they did next.

Scans, views and clicks. A scan belongs to a QR code (the Codes screen). A view and a click belong to a link page. When a QR code opens a link page, one scan normally leads to one view, and then perhaps some clicks. The percentage is of visitors, not of clicks, so it cannot go above 100% however many buttons people press.

Reading the statistics

  • Views: how many times the page was opened. Unique visitors: each person once a day. Via a QR code: views that came from one of this page's QR codes. Button clicks: how many times a web button was pressed. Pressed a button: the share of unique visitors who pressed at least one button (never more than 100%). The next part explains the difference between views and clicks.
  • Views over time: a chart by day (UK time) for the last 30 days.
  • Clicks on each button: which links people use, with the time of the last click. Email and phone buttons open the visitor's own app directly, so their taps cannot be counted.
  • Boxes below show where views came from (QR code or a direct link), device, operating system, language, country and referring site. Bots, such as link previews in chat apps, are left out.

Changing, switching off and deleting

  • Edit changes anything. Buttons you keep stay the same button, so their click history is kept. A button you remove takes its own history with it from the list.
  • Changing the page address: QR codes made with Make a QR code for this page follow the page to its new address automatically. Links you shared anywhere else (a social profile, an email, a printed address) stop working, so avoid changing it once a page is out.
  • Switch off takes the page down without deleting it: visitors see "Page not found". Switch on brings it back.
  • Delete removes the page and its statistics for good. Codes that pointed at it keep working but lead to "Page not found".

Good to know

  • Link pages follow the same privacy rules as QR codes (see What is tracked): no names, no cookies, and the visitor's address is only stored in a scrambled, daily-changing form. Records are deleted after the retention period.
  • Pages are marked so that search engines do not list them.
  • The three companies and their logos are built in. Adding a fourth company is a small change for a developer (a logo and a colour).
  • Logos and social icons are used only to identify the company and the services you link to.

What it is. The people who can sign in. {{if .Data.IsAdmin}}Open Users in the menu.{{else}}Only admins see the Users page; ask an admin if you need something changed.{{end}}

  • Roles. An admin can do everything, including managing users. A member can make and manage QR codes, campaigns and designs and read all the statistics, but cannot manage users.
  • Add a user. Enter a user name (3 to 32 letters, numbers, dots, dashes or underscores), choose a role, and either type a temporary password (at least 12 characters) or leave it blank to have one generated. A generated password is shown once on the screen: copy it and pass it to the person securely. The new person must choose their own password when they first sign in.
  • Reset a password. Press Reset password next to the person (blank for a generated one). They are signed out everywhere, their old password stops working, and they must choose a new one at next sign-in. Use this for forgotten passwords.
  • Change a role. Pick the role and press Save. The person is signed out so the change takes effect cleanly.
  • Remove a user. Press Remove and confirm. They are signed out at once and can no longer sign in. QR codes they made stay.
  • Safety rules. You cannot remove yourself, and the last admin can never be removed or made a member, so the system can never be left with nobody in charge.
  • Recent activity lists who did what and when (creating codes, adding users, resetting passwords, saving designs...). It never records passwords.

21. Your account: signing in and your password

  • Signing in. The user name is not case sensitive; the password is. After five wrong tries within 15 minutes from one place you are locked out for 15 minutes; waiting is enough, and an admin can reset your password if you have forgotten it.
  • First sign-in. You are taken straight to Change password. Enter the temporary password, then your own new one twice. It must be at least 12 characters (up to 72); three or four random words is easy to remember and strong. A Show passwords tick lets you check what you typed.
  • Changing your password later. You can open the same page again from the address /admin/password. Changing it signs out your other sessions.
  • If every admin is locked out or has forgotten their password. Another admin can reset it from the Users page. If nobody can sign in, whoever looks after the server can run Reset a QR tracker password (a GitHub Actions workflow) or qrtrack resetpassword NAME on the server. It prints a one-time temporary password, forces a change at next sign-in, signs that user out everywhere and clears all lockouts.
  • Staying signed in. You are signed out after 12 hours of inactivity, and in any case after 7 days.
  • Signing out. Use Sign out at the top, especially on a shared computer.

23. Troubleshooting and questions

My printed code will not scan.
Check the size (at least about 2 cm), the blank border, and the contrast (dark on light). Scan it from different distances with two phones. Try error correction H and a simpler design (square dots, no logo). For a dynamic code, check the code is not disabled and its window has not ended with show expired page.
The form says the design is "too close to the background".
The code colour is too pale or too similar to the background. Choose a darker code colour or a lighter background.
"That is too long to fit in a QR code."
A static code holds its content directly, so very long text or a big contact card does not fit. Shorten it, or make it a dynamic code (which only holds a short address).
I want to change where a printed code goes.
Only dynamic codes can be changed. Open it, press Edit and change the address. A static code can never be changed; make a new one.
I made a static code but want tracking.
That is not possible. Make a new dynamic code and use that one from now on.
The scan count looks too low.
Only people are counted, and only while the window is active. Bots, link previews and scans before the start date are not counted. Check the dates, press Include bots to see the robots, and remember a scan limit stops counting.
The scan count looks too high.
Several people may be scanning, and All scans counts repeat visits by the same person. Look at Unique for different visitors.
The town is wrong.
Towns are estimates from the visitor's internet address. Mobile networks and VPNs often show the wrong one. Use country, and treat regions and towns as a guide.
I cannot sign in.
Check Caps Lock (the password is case sensitive), try again with the Show password tick if available, and wait 15 minutes if you have had five wrong tries. If you still cannot, ask an admin to reset your password.
The page says "Admins only".
You are signed in as a member. Ask an admin if you need a user managed.
The bulk upload failed.
Read the list: it names the spreadsheet row and the problem. Check the headings are exactly label and url, that every address starts with https://, and that the file is saved as CSV.
I deleted a code by mistake.
It cannot be undone. A dynamic code that was printed will now show "Link not found". Make a new one and, if you still have the old printed copies, replace them.
Who can see my scans?
Everyone who is signed in, admins and members. Visitors never can. See What is tracked.
Can I delete one person's scan?
No. Scans carry no name or address, so one person's cannot be picked out. Deleting a QR code or link page deletes all its records, and everything is removed automatically after the retention period.
Where do I find the scans in a spreadsheet?
On a code's page press Export CSV, or press Export scans in the menu for every code.

24. What this system does not do

So you are not looking for something that is not there:

  • It does not host files or general web pages: there is no PDF, MP3, video, menu or landing-page code. The only hosted pages are Link pages. To send people to a PDF or video, use Website link to point at one that already lives on blake-uk.com or YouTube.
  • It does not run advertising or retargeting pixels (Google Tag Manager, Facebook pixel), which would slow every scan and need a cookie banner.
  • It has no public interface for other software yet, no two-factor sign-in, and no email alerts.
  • Campaigns are a single list, not folders.
  • Link pages count views and button clicks but are not exported to CSV, and a page cannot yet be copied to start a new one.

25. Glossary

Bot
A program, not a person, that visits addresses automatically.
Button click
One press of a web button on a link page. One visit can make several, or none.
Campaign
A label for where a code is used.
CSV
A plain spreadsheet file that Excel and Google Sheets can open and save.
Dynamic code
A tracked code whose destination can be changed.
Error correction
Extra information in the code that lets it scan even when damaged.
PNG
A common picture format with a fixed number of pixels.
Quiet zone
The blank border round a code. Scanners need it.
Referrer
The site or app a visitor came from.
Scan
One person scanning a dynamic QR code. Counted on the code, not on a link page.
Static code
An untracked code that holds its content itself.
SVG
A picture format that can be made any size without going blurry.
Tracking address
The short web address inside a dynamic code.
Unique visitor
A person counted once in a 24-hour period.
View
One opening of a link page. A reload or return visit counts again; Unique visitors counts a person once a day.
